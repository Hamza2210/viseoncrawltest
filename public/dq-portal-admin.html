User & Organisation Administration

Create organisations and users, manage access and on-premises agents.

Create Organisation

Each organisation gets its own isolated tenant, folder and data. Use a tenant value of your own, such as the organisation's domain, not a Qlik *.qlikcloud.com one.

Tag Management

Your organisation's tags, what each is for, and who may see what.

Your organisation's tags

This is the list people choose from when tagging a dataset. Tick restricts to make a tag an access control: a dataset carrying it is then visible only to members granted it. Admins always see everything. A colour is worn everywhere the tag appears; auto keeps the colour made from its name.

Unsaved changes

Who holds what

Grant each member the restricting tags they may see. Saved as you click. A member granted none sees only datasets that no restricting tag covers.

On-premises Agents

A small Windows service inside the customer's network: it polls for work, runs the assessment there, and keeps the database password on that machine.

Register an agent

Registering names the machine. Its config, downloaded from its row, is what lets it work. See docs/ONPREM_AGENT_INSTALL.md.

Agents

A dot shows each machine's health: green online, amber not heard from lately, red offline or revoked.

Extension Keys

The API key a Qlik Cloud extension is given. Each one belongs to a single Qlik tenant and a single environment, and reaches that tenant's data and nothing else.

Issue a key

The key is shown once, here, when it is issued. Only its hash is kept, so it cannot be shown again. A tenant can hold more than one, so a new key can go in before the old one is revoked.

Keys by tenant

Every key issued, under the tenant it belongs to, with the environment it works in. Revoking one stops it within a minute, and cannot be undone.

Storage

Where your organisation's files are kept: VISEON's storage, or an S3 bucket of your own, where you can see every file the platform writes and reads.

DifferentiaDQ PORTAL · ADMIN

User & org administration

Create an organisation (its own isolated tenant), then create users who can log in to the portal.

Create organisation

Each org gets its own isolated tenant folder. Use a distinct tenant URL (e.g. your domain) - not a Qlik *.qlikcloud.com value.

Create user

Creates the user and emails them a secure link to set their own password, then provisions them for the chosen org.

Tag access

Restrict who can see a dataset by its tags. A tag is ordinary metadata until you list it here, so nothing changes until you do - and tags you already use for grouping keep working as they are.

Pick a colour and the tag wears it everywhere it appears - the picker, the dataset rows and the Assess-by-tag page. Leave it on auto and it keeps the colour generated from its name, which is already distinct per tag; choosing one only matters when you want a specific tag to read a specific way.

This is the list people choose from when tagging a dataset, so a tag can never be declared here under a spelling the data does not use. Tick restricts to turn one into an access control: a dataset carrying it is then visible only to members granted it. Admins always see everything.

Who holds what

Grant each member the tags they may see. Leave empty for a member who should see only unrestricted datasets.

Users

Everyone provisioned for your organisation. Deleting a user removes their Auth0 login and their portal access - this can't be undone.

On-premises agents

An agent lets Data Assurance assess a database that is not reachable from the internet. You run it inside your own network; it polls us for work and opens nothing inbound, and the database password stays on that machine rather than with us. See docs/ONPREM_AGENT_INSTALL.md.
